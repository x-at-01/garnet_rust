# WeDB 性能评测


## 1. 环境与配置

- 写入规模: 顺序 500,000 ops / 随机 500,000 ops

- 读取规模: 500,000 ops

- 数据规模: 约 1002.7 MB (1,035,986 条记录)

- 累计操作数: 4,110,000 次操作

- 载荷大小: 1000 字节 (Key: 9 ~ 16 字节)

- 内存预算: 256 MB

- 常驻内存峰值: 1708.36 MB

- 存储引擎直测，无外置缓存


## 2. 架构对比

- **WeDB**: 混合日志 + 64B 无锁哈希索引。特点：内存划分可变区与只读区，热数据原位就地更新，冷数据无锁追加尾部；LightEpoch 协调无锁并发；原生异步 I/O；适用点读写与微秒级响应。

- **WeDb-BfTree**: 块级有序 B 树与磁盘分页（对标 Garnet BfTree）。特点：定长块分页，分段条带并发锁；叶子节点内存缓存与页内就地更新；带缓存块级文件 I/O；适用范围扫描与有序切片。

- **RocksDB**: 多层级 SSTable 与内存跳表。特点：写入追加 Memtable 与顺序刷写 WAL；后台分层合并回收无用键并进行块压缩；点读依赖布隆过滤器与块缓存；适用持久化与高压缩比。

- **Fjall**: LSM 架构与 WAL。特点：标准库同步文件 I/O，支持多线程安全共享与快照读；通过分层 SSTable 合并保证有序迭代；适用有序嵌入式存储。

## 4. 技术分析

1. 就地更新: WeDB 在 HybridLog 可变区就地更新，不追加 WAL，无 Compaction；LSM-Tree（RocksDB 与 Fjall）追加 Memtable，触发后台 Compaction 与写放大。


2. 点读定位: WeDB 通过 64B 哈希索引定位记录，时间复杂度 O(1)；WeDb-BfTree 通过内存页缓存检索 B 树节点；RocksDB 与 Fjall 需检索 Memtable、BloomFilter 与 Block Cache。


3. 并发扩展: WeDB 基于 LightEpoch 协调，各线程使用独立 Session 与原子追加；WeDb-BfTree 采用条带锁并发；RocksDB 并发写入受互斥锁批处理限制。


4. 范围查询: 四引擎统一纯 KV 有序扫描口径（WeDB 直接驱动底层 BfTree 原始 KV 扫描，不经 ZSet 上层路径）；WeDb-BfTree 对标 Garnet BfTree 块级分页，RocksDB 与 Fjall 支持全量持久化键字典序扫描。


5. 空间占用: LSM-Tree 采用后台分层合并与块压缩，空间放大低于 1.0x；WeDB 采用分段日志追加，空间放大约 1.08x。
